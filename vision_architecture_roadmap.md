# 🚀 QuestionShaper: Ultimate Vision & Enterprise Architecture Roadmap

> **Vision Statement:** To build Bangladesh's most powerful, AI-driven EdTech "Knowledge Engine." It starts as a closed-door centralized data factory converting curriculum books into a vectorized "Brain" (Knowledge Hub) and scales into a massive platform serving millions of students/teachers with auto-generated exams, lecture sheets, ERP, OMR capabilities, and personalized RAG-based AI Guidance.

---

## 🏗️ Phase 1: The "Knowledge Factory" (বর্তমান ফেইজ)
* **Goal:** Selected Admins digitize, proofread, and vectorize the entire curriculum.
* **Target Audience:** Internal Super Admins, Subject Matter Experts (SMEs).
* **Current Server Suitability:** Your current Google Cloud 2-Core, 8GB RAM Linux VPS is **absolutely perfect** for this phase. Using "Pay-as-you-go" Gemini API keys allows bypassing limits.

### Technical Action Items:
1. **Dynamic Frontend-Controlled Thread Pooling:** Implement a UI inside `reports/knowledge-hub` allowing Admins to set the live worker count (e.g., dynamically jump from 6 to 100 threads instantly based on server load and API limits) without restarting the VPS.
2. **Complete Phase 3D (Pinecone Vectorization):** Vectorize the "Golden Data" and push to Pinecone. This is the foundation of your future "Brain".
3. **Advanced Reporting UI:** Include a Live Terminal Error Log console and API request tracker in the Server & Jobs React Dashboard.
4. **Database Guardrails:** Optimize your JVM and HikariCP connection pools to ensure massive dynamic threading (100+ parallel extractions) does not cause connection exhaustion to MySQL.

---

## 🧠 Phase 2: The "EdTech Engine & RAG" (সেমি-পাবলিক ফেইজ)
* **Goal:** Launch the core tools based on the Vector Brain—Question Bank, Exam Generation, Lecture Sheets, and the Doubt Solver Chatbot.
* **Target Audience:** Teachers, Institutions, and early access students.
* **Architecture Shift:** The current Monolithic architecture must be split into two isolated modules.

### Technical Action Items:
1. **Microservice Decoupling:** 
   - **Service A (Core API):** Handles Logins, Institution Dashboards, Billing, and File requests.
   - **Service B (AI Worker Network):** A separate Spring Boot instance dedicated exclusively to Gemini/OpenAI calls, Question Generation, and Chatbot RAG pipelines.
2. **Vector Retrieval Architecture:** Set up standard RAG (Retrieval-Augmented Generation) so the Chatbot only answers based on the *Proofread Golden Vectors* in Pinecone, preventing AI hallucinations.

---

## 🌍 Phase 3: Massive Public Scaling (High Variability Traffic)
* **Goal:** Open up to millions of users. Teachers rendering massive PDFs, students solving doubts real-time, and schools downloading huge exam templates.
* **Target Audience:** Millions of concurrent Teachers, Students, Coaching Centers.
* **Architecture Shift:** Moving to Distributed Elastic Cloud architecture.

### Technical Action Items:
1. **Horizontal Auto-Scaling:** Deploy via Kubernetes (GKE) or Managed Instance Groups (MIG). If traffic spikes before school exams, GCP will automatically clone your Core API server from 1 to 5 instances, and kill them back to 1 when traffic drops.
2. **Cloudflare CDN / Origin Caching:** All generated PDFs (Exams, Lecture Sheets) and R2 images must be cached at the Cloudflare Edge network. The core server should never serve static files twice.
3. **Database Read/Write Replicas:** 
   - 1 Master DB (Only for inserts/updates like adding a question).
   - 2+ Read-Replica DBs (For fetching dashboards and reading lists). This eliminates query bottlenecks.

---

## 📈 Phase 4: ERP, OMR & AI Analytics Ecosystem
* **Goal:** Close the student performance loop. Exams generated by QuestionShaper $\rightarrow$ Taken by Students $\rightarrow$ Evaluated by OpenCV OMR engine $\rightarrow$ Synced to ERP $\rightarrow$ Analyzed by AI for personalized guidance.
* **Target Audience:** Entire Educational Ecosystem Management.
* **Architecture Shift:** Embracing Big Data, Edge processing, and specific Data Analytics pipelines.

### Technical Action Items:
1. **WPF/Local OMR Integration Engine:** The SaaS backend exposes highly secure gRPC / GraphQL endpoints to sync data between the heavy offline Windows OMR scanner app and the Cloud ERP.
2. **Data Streaming & Analytics Lake:** With millions of OMR bubbles generating data, we must decouple logging. Send exam scores, performance tracking to an Apache Kafka or Redis stream, eventually sinking into an OLAP database (like ClickHouse or Google BigQuery) designed for analytics.
3. **Performance Dashboard & Alerting:** Build the "Personalized Guidance Logic." AI queries the Analytics Lake to detect patterns (e.g., "Student X fails 80% of 'Higher Evaluation' Biology questions") and automatically pushes customized lecture sheets natively via Pinecone.
